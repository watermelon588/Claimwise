# Feasibility and rollout

**Status:** Draft proposal. Claims about measured performance and formal test results belong in the validation evidence. The starting point is a synthetic-data prototype.

## What can be demonstrated

| Area | Evidence today | Gate for expanded use |
| --- | --- | --- |
| Evidence preparation and claim review | Repository includes structured document intake, evidence review, pack export and deterministic payment matching. | Review accuracy with representative cases and establish human escalation for ambiguous evidence. |
| Provider workflow | Mock service and gateway implement synthetic reads, authorized submission and status recovery. | Confirm partner access, identity mapping, allowed actions and receipt semantics. Use manual channels while access is unverified. |
| Grievance and specialist routes | The prototype drafts letters and records user-reported filing. Official public channels document their processes. | Verify case-specific eligibility and current timing with official sources and human review. [S-06 and S-29](../02-research/sources.md) |
| Hosted demo | Frontend config and host setup are documented. Backend and mock use persistent storage for durability. | Set real HTTPS origins, confirm streaming and downloads, and keep the synthetic demo isolated from real claim data. |

## Cost and effort model

Estimate monthly cost as fixed service hosting plus storage and database usage, model calls, and human review. Count document extraction, chat and intent calls separately. Multiply input and output tokens by the active model rates, including fallback and retry usage where it occurs. Track uploaded and generated bytes, database compute/storage, and outbound downloads. Use observed call counts and document sizes from a representative run before projecting per-case cost. Partner fees and support staffing are open inputs.

| Input | Basis |
| --- | --- |
| Models | Account usage and current model rates. [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing) · [Groq models and rates](https://console.groq.com/docs/models) |
| Case storage | Active cases, retained checkpoints, upload volume, and required storage duration. [Neon pricing](https://neon.com/pricing) · [Render disks](https://render.com/docs/disks) |
| Pilot operations | Number of cases multiplied by review, handoff, and exception-handling effort. Staff time and provider access are planning assumptions. |

## Proposed pilot and recovery

Start with a supervised synthetic walkthrough. Include a patient, a caregiver and a multi-cover household across several cases. Ask reviewers to identify the next responsible actor, correct a source fact, and show evidence for the final outcome. Only consider a limited real-user pilot after the identity, permissions, storage, deletion, and partner gates are approved.

- **Outcome measures:** proportion of cases with evidence-backed next actions and completion, first-pass pack acceptance where receipts exist, and the number of unresolved or repeated requests.
- **Failure measures:** wrong case access, stale or unapproved actions, duplicate submissions, ambiguous provider writes and unreconciled payments. Track incidents as counts and record the affected stage and evidence.
- **Stop and recover:** pause writes on an authorization or isolation incident. Preserve receipts and reconcile in-flight requests with the provider before any retry. Revoke the affected connection and continue through human handoff when appropriate.
- **Roll back:** disable the affected hosted integration or preview, restore the previous reviewed deployment where available, and reconcile external actions separately. A deployment rollback cannot undo a provider action already accepted.
